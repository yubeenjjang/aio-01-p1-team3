# 05-3｜화면 설계서 (SSE·멀티턴·AI 분석 평가 확장)

> **구현 동기화 기준(2026-08-11):** 합의된 두 탭 UI, 120초 그룹 갱신, 관리자 공용 SSE 큐, 사용자 사이드바의 마이페이지 최종 배치와 현재 오류 처리를 반영합니다.

## 1. 화면 범위

이 문서는 [05 SSE·멀티턴 AI 확장 계획서](./05_SSE_멀티턴_AI_확장_계획서.md)의 사용자·관리자 화면 상세 설계입니다.

핵심 화면은 기존 사용자 AI 분석 페이지를 확장한 `09_analysis.py`와 관리자 운영 로그·분석 평가 화면입니다.

- 사용자: AI 분석과 일반 학습 코치를 한 화면의 두 탭으로 제공
- 사용자: 분석 결과 아래에 평가 입력 제공
- 관리자: 대시보드·운영 로그·분석 평가가 공용 SSE 큐로 필요한 데이터를 갱신
- 관리자: 사용자 분석 평가 목록·통계·의견 조회
- 그룹 스터디: 소유자 삭제와 목록·상세 120초 자동 갱신 제공
- 사용자 공통 사이드바: 주요 기능 메뉴와 사용자 영역을 분리하고 사용자 정보 아래에 마이페이지 이동 버튼 제공

## 2. 정보 구조

```text
사용자 프론트엔드
└── AI 분석 (09_analysis.py)
    ├── 분석 기간 선택
    ├── 2개 탭
    │   ├── AI 분석 탭
    │   │   ├── 분석 실행
    │   │   ├── 결과
    │   │   ├── 오류·재시도
    │   │   └── 사용자 평가
    │   └── AI 코치 탭
    │       ├── 대화방 목록
    │       ├── 대화방 생성·삭제
    │       ├── 메시지 이력
    │       └── 질문 입력

관리자 프론트엔드
├── 대시보드
├── 운영 로그
└── AI 분석 평가
    ├── 평균 평점·분포
    ├── 평가 목록·필터
    └── 의견 상세
※ 세 화면 모두 관리자 SSE 수신 리스너와 큐를 공유하고 5초마다 큐만 확인
```

### 2.1 사용자 사이드바 최종 변경

MVP 화면 설계서의 사이드바 메뉴 순서는 아래 최종 배치로 대체합니다.

```text
오케퐁터디
함께 기록하고 성장하는 학습 관리 서비스
────────────────────────
메뉴
├── 메인
├── 개인 스터디
├── 그룹 스터디
└── AI 분석
────────────────────────
사용자 이름
역할
[마이페이지]
[로그아웃]
```

- 마이페이지는 주요 기능 메뉴의 `st.page_link` 목록에서 제외합니다.
- 사용자 이름·역할 아래, 로그아웃 버튼 위에 전체 너비의 별도 버튼으로 배치합니다.
- 버튼을 누르면 등록된 `mypage` Page 객체를 `st.switch_page(mypage)`에 전달해 `app_pages/10_mypage.py`로 이동합니다.
- 마이페이지 버튼은 사용자 계정 영역임을 구분할 수 있도록 보라색 계열로 강조합니다.
- 로그인 전에는 기존과 같이 사용자 사이드바를 표시하지 않습니다.

### 2.2 그룹 스터디 화면 최종 변경

- 목록과 상세 화면은 120초마다 조회 API를 호출하며 수동 새로고침도 제공합니다.
- 상세 화면은 소유자에게만 삭제 확인 UI를 표시합니다.
- 확인 후 `DELETE /studies/{study_id}?user_id=`를 호출하고 성공하면 목록으로 이동합니다.
- `403 STUDY_OWNER_REQUIRED`, `404 STUDY_NOT_FOUND`는 공통 오류 형식으로 표시합니다.

## 3. 사용자 AI 분석 화면

### 3.1 기본 레이아웃

```text
┌──────────────────────────────────────────────────────────────┐
│ AI 학습 분석                                                 │
│ [AI 분석 탭] [AI 코치 탭]                                    │
├──────────────────────────────────────────────────────────────┤
│ 선택한 탭의 분석·평가 또는 대화방·메시지 UI                  │
└──────────────────────────────────────────────────────────────┘
```

Streamlit에서는 `st.tabs(["AI 분석", "AI 코치"])`를 사용해 좁은 화면에서도 각 기능의 폭과 가독성을 유지합니다.

### 3.2 분석 기간·실행 영역

| 요소 | 동작 |
| --- | --- |
| 시작일 | 날짜 입력, 종료일보다 늦을 수 없음 |
| 종료일 | 날짜 입력, 미래 날짜 선택 제한은 기존 정책 적용 |
| 분석 실행 | 기간 검증 후 `POST /analyses` 호출 |
| 로딩 | 버튼 비활성화, 분석 중 안내 표시 |
| 성공 | 요약·강점·개선점·다음 목표 표시 |
| 기록 없음 | `NO_STUDY_RECORDS` 안내와 기록 작성 이동 버튼 표시 |
| 429 | 호출 한도 안내와 재시도 버튼 표시 |
| 503 | Gemini 장애 안내와 재시도 버튼 표시 |
| 500 | 일반 분석 오류와 재시도 버튼 표시 |

분석 결과는 사용자가 선택한 기간과 함께 화면 상태에 보관합니다. 페이지를 새로고침하면 해당 기간으로 평가를 조회해 기존 평가를 복원합니다.

### 3.3 사용자 평가 영역

분석 결과 아래에 배치하며, 분석 결과가 성공한 뒤에만 활성화합니다.

| 요소 | 규칙 |
| --- | --- |
| 평점 | 1~5점, 필수 입력 |
| 의견 | 선택 입력, 최대 1000자 |
| 평가 저장 | `POST /analyses/feedback`, 저장 중 중복 클릭 방지 |
| 기존 평가 | `GET /analyses/feedback`으로 복원하고 수정 모드로 표시 |
| 저장 성공 | `평가가 저장되었습니다` 표시, 저장 시각 갱신 |
| 검증 오류 | 평점 선택·의견 길이 오류를 입력 영역에 표시 |
| 네트워크 오류 | 공통 API 오류 메시지와 재시도 버튼 표시 |

권장 문구:

> 이번 분석이 학습에 얼마나 도움이 되었나요?

사용자에게 관리자에게 평가가 공유될 수 있음을 평가 입력 영역 근처에 안내합니다.

### 3.4 일반 학습 코치 탭

| 영역 | 동작 |
| --- | --- |
| 대화방 선택 | `GET /chat/conversations` 결과를 최근 수정순으로 표시 |
| 새 대화 | `POST /chat/conversations` 후 새 대화방 선택 |
| 삭제 | 확인 후 `DELETE /chat/conversations/{id}` 실행 |
| 메시지 이력 | 선택 대화방의 `GET .../messages` 호출 |
| 메시지 표시 | `user`와 `model`을 다른 색상·정렬로 구분 |
| 질문 입력 | 빈 문자열 전송 차단, 전송 중 버튼 비활성화 |
| 답변 성공 | user/model 메시지 표시 및 대화방 목록 갱신 |
| 429·503·500 | 오류 종류별 안내와 재시도 버튼 표시 |

채팅은 선택한 분석 기간에 자동으로 결합하지 않습니다. 사용자가 일반 질문을 직접 입력하는 독립 학습 코치이며, 필요하면 질문에 분석 결과를 참고하도록 안내합니다.

## 4. 사용자 화면 상태

| 상태 | AI 분석 탭 | AI 코치 탭 |
| --- | --- | --- |
| 최초 진입 | 기간 선택·분석 실행 안내 | 대화방 없음·새 대화 버튼 |
| 로딩 | 분석 결과 영역 spinner | 메시지 영역 spinner, 전송 비활성화 |
| 성공 | 결과·평가 영역 표시 | 메시지 이력 표시 |
| 빈 상태 | 분석 실행 전 안내 | 선택 대화방 없음 안내 |
| 오류 | 표준 코드·메시지·재시도 | 표준 코드·메시지·재시도 |
| 부분 성공 | 분석 결과는 유지하고 평가 오류만 표시 | 채팅 오류가 AI 분석 탭을 가리지 않음 |

분석 오류와 채팅 오류는 서로의 탭 상태를 덮어쓰지 않습니다.

## 5. 관리자 운영 로그 화면

### 5.1 구성

```text
┌──────────────────────────────────────────────────────────────┐
│ 운영 로그                         [실시간 연결됨] [새로고침]   │
│ 상태 [전체▼]  action [전체▼]  limit [50]                    │
├──────────────────────────────────────────────────────────────┤
│ created_at | action | status | message | latency | trace_id   │
│ ...                                                          │
└──────────────────────────────────────────────────────────────┘
```

### 5.2 SSE 동작

1. 관리자 로그인 후 세션별로 `GET /events/stream?admin_user_id=` 연결을 하나 생성
2. 대시보드·운영 로그·분석 평가 화면이 같은 리스너와 큐를 공유
3. 각 화면 fragment가 5초마다 큐를 확인
4. 관련 `admin.log.updated` 수신 시 현재 필터를 유지하고 해당 조회 API 재호출
5. 연결 오류 시 백그라운드 리스너가 5초 후 재연결하며 수동 새로고침은 계속 활성화
6. 일반 사용자 화면에는 SSE 연결을 생성하지 않음

각 관리자 화면은 5초마다 SSE Queue만 확인합니다. 이벤트가 없으면 DB/API를 호출하지 않고 캐시된 데이터를 다시 표시하며, 관련 `admin.log.updated` 이벤트가 있을 때만 활성 화면의 조회 API를 재호출합니다. 연결 상태 문구는 안내용이며 실제 Redis 연결·재연결 상태의 세분화는 후속 보완 항목입니다.

SSE 이벤트에는 로그 전체 message나 평가 의견을 담지 않고, 조회 API에서 최신 데이터를 다시 가져옵니다.

## 6. 관리자 분석 평가 화면

새 화면: `frontend_admin/app_pages/03_analysis_feedback.py`

### 6.1 구성

```text
┌──────────────────────────────────────────────────────────────┐
│ AI 분석 평가                                                 │
│ 평균 평점 4.2   응답 수 24   [새로고침]                       │
│ 평점 [전체▼]  기간 [시작] ~ [종료]  [조회]                    │
├──────────────────────────────────────────────────────────────┤
│ 평가일 | 사용자 | 분석 기간 | 평점 | 의견                    │
│ ...                                                          │
└──────────────────────────────────────────────────────────────┘
```

### 6.2 동작

| 요소 | 동작 |
| --- | --- |
| 평균 평점 | `GET /admin/analysis-feedback`의 `average_rating` 표시 |
| 평점 필터 | 1~5점 선택 후 조회 |
| 날짜 필터 | 평가 생성일 기준 `from`, `to` 전달 |
| 목록 | 평가일·사용자명·분석 기간·평점·의견 표시 |
| 긴 의견 | 표에서는 줄임 표시, 선택 시 전체 표시 |
| 실시간 갱신 | 관리자 SSE의 `admin.log.updated` 수신 후 평가 목록 재조회 |
| 권한 오류 | `ADMIN_REQUIRED` 안내 후 관리자 로그인 화면으로 이동 |
| API 오류 | 데모 데이터를 대신 표시하지 않고 오류 코드·trace ID·재시도 버튼을 표시 |

개인정보 보호를 위해 사용자 이메일·비밀번호·민감한 학습 기록 본문은 표시하지 않습니다.

## 7. 화면별 API 연결

| 화면 | API | 용도 |
| --- | --- | --- |
| 사용자 AI 분석 | `POST /analyses` | 기간별 AI 분석 |
| 사용자 AI 분석 | `GET/POST /analyses/feedback` | 평가 조회·저장·수정 |
| 사용자 AI 분석 채팅 | `GET/POST /chat/conversations` | 대화방 목록·생성 |
| 사용자 AI 분석 채팅 | `GET/POST /chat/conversations/{id}/messages`, `DELETE /chat/conversations/{id}` | 메시지 이력·질문·대화방 삭제 |
| 관리자 운영 로그 | `GET /admin/logs` | 로그 목록·필터 |
| 관리자 운영 로그 | `GET /events/stream` | 로그 변경 실시간 감지 |
| 관리자 평가 | `GET /admin/analysis-feedback` | 평가 목록·통계 |

## 8. 구현·검증 체크리스트

### 사용자

- [ ] 사이드바의 주요 기능 메뉴에는 메인·개인 스터디·그룹 스터디·AI 분석만 표시된다.
- [ ] 사용자 이름·역할 아래, 로그아웃 위에 마이페이지 버튼이 표시되고 정상 이동한다.
- [ ] 분석 기간 오류가 AI 분석 탭 안에서만 표시된다.
- [ ] 분석 성공 후에만 평가 영역이 활성화된다.
- [ ] 평가 생성·수정·새로고침 복원이 동작한다.
- [ ] 채팅 대화방 생성·선택·삭제가 동작한다.
- [ ] 두 번째 질문에 이전 user/model 메시지가 반영된다.
- [ ] 분석과 채팅 오류가 서로의 상태를 오염시키지 않는다.

### 관리자

- [ ] 일반 사용자 화면에서 SSE 연결이 발생하지 않는다.
- [ ] 관리자 대시보드·로그·평가 화면이 하나의 SSE 연결과 큐를 공유한다.
- [ ] 로그 이벤트 수신 후 기존 필터가 유지된 채 목록이 갱신된다.
- [ ] 평가 화면에서 평균 평점·목록·의견을 확인할 수 있다.
- [ ] 평가 등록 직후 관리자 로그·평가 목록이 갱신된다.
- [ ] 일반 사용자가 관리자 로그·평가 API를 호출하면 403을 받는다.

### 공통

- [ ] 400·403·404·429·503·500 오류가 공통 형식으로 표시된다.
- [ ] 로딩 중 중복 요청이 차단된다.
- [ ] API 오류에도 수동 새로고침이 가능하다.
- [ ] trace ID가 오류 화면 또는 관리자 로그에서 확인된다.
