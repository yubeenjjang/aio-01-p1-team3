[README로 돌아가기](../../README.md) · [상세 MVP 설계](../03_화면_설계서_MVP.md) · [상세 확장 설계](../05-3_화면_설계서_확장.md)

## 1. 최종 화면 정보 구조

```text
사용자 프론트엔드
├── 메인: 학습 통계·최근 기록
├── 개인 스터디: 학습 기록 CRUD·인증 이미지
├── 그룹 스터디: 탐색·내 스터디·생성·참여
├── AI 분석
│   ├── AI 분석 탭: 기간 분석·결과·평가
│   └── AI 코치 탭: 대화방·멀티턴 질문
└── 사용자 영역
    ├── 이름·역할
    ├── 마이페이지
    └── 로그아웃

관리자 프론트엔드
├── 대시보드: 핵심 운영 지표
├── 운영 로그: 필터·지연 시간·trace_id
└── AI 분석 평가: 평균·분포·사용자 의견
```

## 2. 화면과 기능의 연결

| 화면 동작 | API·데이터 연결 | 사용자에게 보이는 결과 |
| --- | --- | --- |
| 학습 기록 작성 | Records API → `study_records` | 목록·누적 시간·과목별 통계 |
| 스터디 탐색·참여 | Studies API → `studies`, `study_members` | 참여 중인 그룹과 그룹 탐색을 별도 영역으로 구분 |
| AI 분석 | Analyses API → Gemini | 요약·강점·개선점·다음 목표 |
| AI 코치 질문 | Chat API → 대화·메시지 테이블 → Gemini | 이전 문맥을 반영한 후속 답변 |
| AI 평가 등록 | Feedback API → `analysis_feedback` | 기존 평가 복원·수정·저장 안내 |
| 관리자 로그 확인 | Admin API → `operation_logs` | 상태 필터·처리 시간·trace_id 상세 |
| 관리자 실시간 갱신 | Redis Pub/Sub → SSE → 조회 API | 이벤트가 있을 때 최신 데이터 반영 |

## 3. 핵심 UI/UX 결정

- 사용자와 관리자 앱을 분리해 역할별 정보 밀도를 조절했습니다.
- AI 분석과 AI 코치는 한 화면의 두 탭으로 분리해 작업 문맥을 유지합니다.
- 그룹 스터디는 참여 중인 그룹과 탐색 결과를 별도 영역으로 구분합니다.
- 사이드바의 주요 기능과 계정 영역을 분리하고, 사용자 정보 아래에 마이페이지·로그아웃을 배치합니다.
- 그룹 스터디 목록·상세는 120초 자동 갱신과 수동 새로고침을 제공합니다.
- 관리자 화면은 공용 SSE 큐를 최대 5초마다 확인하고 이벤트가 있을 때만 데이터를 다시 조회합니다.

## 4. 정상 화면 이외의 상태

| 상태 | 화면 처리 |
| --- | --- |
| Loading | Spinner·버튼 비활성화로 중복 요청 방지 |
| 빈 데이터 | 기록 등록·스터디 생성·새 대화 등 다음 행동 안내 |
| 입력 오류 | 해당 필드와 가까운 위치에 검증 메시지 표시 |
| API 오류 | 표준 코드·메시지·trace ID와 재시도 제공 |
| 부분 성공 | AI 분석 결과는 유지하고 평가·채팅 오류만 분리 표시 |
| 외부 AI 오류 | 429·503·500을 호출 한도·장애·일반 오류로 구분 |
